# Цветочный бот

Личный Telegram-бот про комнатные растения.

- Присылаешь фото цветка, бот коротко отвечает: что это, всё ли с ним ок, норм ли горшок, как часто поливать и что сделать прямо сейчас. Скан идёт около минуты.
- После сохранения нового цветка спрашивает, когда был последний полив, и считает следующий от этого дня.
- Утром (с 9:00 по Москве) пишет, кого пора полить. Вечером (с 19:00) напоминает, если кто-то остался.
- В чате есть кнопка «Мои цветы». Она открывает приложение со списком цветов, отметками полива и сканером.
- Цветами можно поделиться (Цветы → Поделиться цветами): гость по ссылке видит их, отмечает полив и получает напоминалки, но не удаляет и не меняет.

У каждого, кто написал боту, своя коллекция цветов.

## Из чего состоит

| Что | Где |
| --- | --- |
| Сервер бота и приложения (Node.js 22) | хостинг [Railway](https://railway.com), регион лучше рядом с базой |
| База: люди, цветы, поливы, гостевой доступ | [Supabase](https://supabase.com), таблицы `users`, `plants`, `waterings`, `shares` |
| Фото цветов | Supabase Storage, бакет `photos` |
| Сканер: одна модель смотрит на фото, вторая пишет вывод и советы | [OpenRouter](https://openrouter.ai) |
| Определение вида по фото (база культурных и декоративных растений), подсказка сканеру | [Pl@ntNet API](https://my.plantnet.org), необязательно, 500 запросов в день бесплатно |
| Режим полива и свет для вида, подсказка сканеру | [Perenual API](https://perenual.com/docs/api), необязательно, 100 запросов в день бесплатно |

```
src/
  index.js      веб-сервер: вебхук Telegram, API приложения, часы для напоминалок
  bot.js        что бот делает в чате
  scan.js       запрос к моделям и разбор ответа
  references.js справочники Pl@ntNet и Perenual
  db.js         работа с Supabase
  telegram.js   запросы к Telegram, проверка, кто открыл приложение
  timing.js     замер времени запросов, строчки «⏱» в логах
  config.js     настройки из переменных окружения
  dates.js      даты по московскому времени
public/         приложение (Telegram Mini App)
supabase/schema.sql   таблицы и бакет для фото
amvera.yml      настройки для хостинга Amvera (если запускать там)
```

## Запуск

### 1. Бот в Telegram

В [@BotFather](https://t.me/BotFather): `/newbot`, придумать имя, сохранить токен.

### 2. Supabase

1. Создать проект на supabase.com (регион любой, лучше Европа).
2. **SQL Editor → New query**, вставить весь `supabase/schema.sql`, нажать **Run**. Появятся таблицы и бакет для фото. Повторный запуск ничего не ломает, так же добавляются новые таблицы после обновлений.
3. **Project Settings → API**: скопировать **Project URL** и ключ **service_role** (секретный, никому не показывать).

### 3. Railway

1. New Project → Deploy from GitHub repo → этот репозиторий.
2. **Settings → Networking → Generate Domain**: получится адрес вида `имя-production.up.railway.app`.
3. **Settings → Deploy → Regions**: выбрать регион рядом с базой Supabase (для Франкфурта это EU West, Amsterdam). Каждое нажатие кнопки ходит в базу несколько раз, и из Калифорнии в Европу это около полсекунды на запрос.
4. **Variables**:

| Переменная | Что туда |
| --- | --- |
| `BOT_TOKEN` | токен от BotFather |
| `PUBLIC_URL` | домен из шага 2 |
| `SUPABASE_URL` | Project URL из Supabase |
| `SUPABASE_SERVICE_KEY` | ключ service_role |
| `LLM_API_KEY` | ключ OpenRouter (необязательно: без него не работает только сканер) |

Необязательные: `LLM_FAST_MODEL` — быстрый скан одной моделью, она сразу смотрит на фото и пишет вывод (по умолчанию `google/gemini-3.6-flash`, пустое значение — быстрый скан выключен); если она не ответила, скан идёт двумя моделями ниже; `LLM_FAST_REASONING` — сколько ей «размышлять» (по умолчанию `low`); `LLM_VISION_MODEL` — модель, которая смотрит на фото (по умолчанию `deepseek/deepseek-v4-flash-vision-exp`); `LLM_TEXT_MODEL` — модель, которая по описанию фото пишет вывод и советы (по умолчанию `~deepseek/deepseek-v4-flash-latest`, пустое значение — всё делает модель для фото); `LLM_BASE_URL` (по умолчанию `https://openrouter.ai/api/v1`, подойдёт любой OpenAI-совместимый адрес); `PLANTNET_API_KEY` — ключ Pl@ntNet: сканер сначала определяет вид там (проект `PLANTNET_PROJECT`, по умолчанию `useful`; движок `PLANTNET_TYPE`, по умолчанию `kt`); `PERENUAL_API_KEY` — ключ Perenual: по найденному виду сканер берёт оттуда норму полива и свет; `LLM_LOOK_REASONING` и `LLM_ADVISE_REASONING` — сколько моделям «размышлять» перед ответом: `low`, `medium`, `high` или `off` (по умолчанию модель для фото `low`, модель для вывода как задумано моделью; меньше размышлений — быстрее скан); `PORT` (по умолчанию 80).

5. Railway сам пересоберёт бота. При старте бот подключает вебхук и кнопку «Мои цветы». В логах должно появиться «Telegram подключён».
6. Написать боту `/start`.

## Логи и скорость

Каждый запрос приложения и каждое событие в чате пишет в лог строчку вида

```
⏱ /api/scan/save: 640 мс · база 5 запр., в сумме 590 мс, самый долгий 160 мс
⏱ фото в чат: 58300 мс · база 4 запр., в сумме 900 мс, самый долгий 400 мс · справочники 2.1 с · модель для фото 31.0 с · модель для вывода 24.6 с
```

По ним видно, где тратится время: в базе (тогда смотреть регион хостинга) или в моделях сканера.

## Настройки в коде

В `src/config.js`: часовой пояс (`TZ_OFFSET_HOURS = 3`), час утренней и вечерней напоминалки, можно выключить вечернюю (`EVENING_NUDGE = false`).

## Проверка у себя

```
npm install
BOT_TOKEN=... PUBLIC_URL=... SUPABASE_URL=... SUPABASE_SERVICE_KEY=... LLM_API_KEY=... PORT=3000 npm start
```

Telegram ходит только на `https`, поэтому для настоящего вебхука нужен публичный адрес.

Сколько шёл каждый скан, на каких шагах и какие модели отвечали, записывается в таблицу `scan_runs` (создаётся в `supabase/schema.sql`).
